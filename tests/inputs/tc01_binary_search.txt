Lecture 6: Binary Search

Searching means finding the position of a target value inside a collection. Linear search checks every element one by one, so in the worst case it looks at all n elements and takes O(n) time.

Binary search is a much faster method, but it only works on a sorted array. The idea is to repeatedly halve the part of the array that could still contain the target.

Algorithm:
1. Set low = 0 and high = n - 1.
2. While low <= high:
   a. Compute mid = low + (high - low) / 2 (integer division).
   b. If arr[mid] equals the target, return mid.
   c. If arr[mid] is less than the target, the target can only be on the right, so set low = mid + 1.
   d. Otherwise the target can only be on the left, so set high = mid - 1.
3. If the loop ends, the target is not present; return -1.

We write mid = low + (high - low) / 2 instead of (low + high) / 2 because adding low and high can overflow when the indices are very large integers.

Complexity:
- Each comparison halves the search space, so the worst-case time complexity is O(log n).
- The best case is O(1), when the middle element is the target on the first comparison.
- The iterative version uses O(1) extra space. A recursive version uses O(log n) space because of the call stack.

Example: searching for 23 in [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]. First mid is index 4 (value 16); 23 is larger, so low becomes 5. Next mid is index 7 (value 56); 23 is smaller, so high becomes 6. Next mid is index 5 (value 23) — found.

Common mistakes: forgetting that the array must be sorted, using low < high instead of low <= high (misses the last element), and updating low = mid or high = mid instead of mid + 1 / mid - 1, which can cause an infinite loop.

Applications: looking up words in a dictionary, finding a value in a sorted database index, and "binary search on the answer" problems where we search over a range of possible answers.
